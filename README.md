# sdzk-gaokao-portal
山东高考报名助手-非官方工具-资料仅保存在山东高考报名助手

面向山东高考考生的报名准备、信息核验与时间管理工具。

山东高考报名助手（Shandong Gaokao Portal）是一个面向考生的非官方辅助项目，致力于将分散的报名信息、准备事项、官方入口与风险核验能力整合到一个简洁、易用、跨设备访问的 Web 界面中。

项目以信息准确性、隐私保护、交互体验和可维护性为核心设计原则，希望帮助考生更清晰地了解报名流程、管理待办事项、核对学校信息，并减少因信息过时、操作遗漏或不实宣传造成的风险。

重要声明：本项目不是山东省教育招生考试院、教育部或任何高校的官方网站，也不代表任何教育主管部门。所有报名资格、报名结果、考试政策及最终操作，均应以主管部门和官方报名系统发布的信息为准。

项目目标

本项目关注的不是简单地展示一组报名链接，而是围绕考生实际使用场景，构建一套清晰、可核验、重视隐私的辅助工作流。

主要目标包括：

* 降低考生查找官方报名信息的成本。
* 提供清晰的报名时间、准备事项和阶段提醒。
* 帮助用户核验高校名称、办学资质和招生信息。
* 尽可能减少重复录入和操作遗漏。
* 在不突破浏览器安全边界的前提下探索合理的资料辅助填报方式。
* 让用户清楚知道哪些信息已核验、哪些仍待确认。
* 优先保护身份证号、联系方式、户籍资料及其他敏感信息。
* 为手机、平板和桌面浏览器提供一致的使用体验。

核心设计原则

1. 官方信息优先

涉及报名时间、报名条件、政策要求、招生资格和高校资质的信息，应优先依据教育主管部门、考试机构及学校官方网站。

第三方页面、网络文章、搜索引擎摘要和社交平台内容只能作为辅助线索，不能自动替代官方证据。

2. 证据优先于结论

项目不应仅凭名称、域名、网络传言或搜索失败就判定一所学校存在问题。

涉及风险的结论，应尽可能提供来源、发布日期、核验时间、适用范围和可直接打开的原始链接。

3. 隐私保护优先

敏感报名资料应按照最小必要原则处理。

在技术条件允许的情况下，优先采用本地处理和本地存储方案，减少不必要的数据传输。任何加密、安全存储或不上传数据的承诺，都必须与实际代码和网络行为一致。

4. 用户保留最终控制权

本项目旨在辅助用户准备和核对信息，不代替考生作出具有法律或考试后果的决定。

涉及报名提交、费用支付、身份验证、验证码和最终确认的操作，应由用户本人在官方系统中完成。

5. 诚实展示功能状态

已经实现、正在开发、计划实现和无法验证的功能必须明确区分。

不得使用静态示例冒充实时数据，不得伪造测试结果，不得将未执行的监测任务描述为持续运行中的服务。

功能规划

以下内容描述项目的目标能力。每项能力是否已完成，应以实际代码、部署版本和测试结果为准。

一、报名信息与官方入口

* 提供山东高考报名官方入口。
* 汇总相关政策和操作指南。
* 展示重要时间节点。
* 根据报名阶段提示需要关注的事项。
* 提供官方原文和来源链接。
* 在信息无法确认时明确提示用户重新核对。

二、报名资料准备

* 为用户提供资料准备清单。
* 帮助用户检查必要字段是否填写完整。
* 对容易遗漏的项目提供提醒。
* 探索安全、可控的资料辅助填报方式。
* 允许用户在提交前逐项检查内容。
* 不擅自代替用户确认最终报名信息。

三、大学名称与风险查询

计划将原有的大面积大学名单展示改为轻量搜索入口。

用户可以输入学校名称，并查看可获得的学校信息、资质核验结果、官方联系方式及相关风险证据。

查询系统应尽可能支持：

* 学校全称和常见简称。
* 学校名称模糊匹配。
* 同名学校区分。
* 官方名单匹配。
* 学校官方网站核验。
* 招生办公室公开电话查询。
* 招生邮箱核验。
* 相关主管部门公告查询。
* 证据来源和最近核验时间展示。

对于无法确认的信息，应显示「待核验」或「暂未找到可靠来源」，不能为了给出答案而编造数据。

四、时间信标

时间信标（Time Beacon）是项目计划探索的提醒系统。

它不仅用于展示倒计时，还希望围绕真实的报名阶段和用户待办事项提供更有针对性的提示。

可能包含：

* 关键日期和截止时间。
* 待完成事项提醒。
* 重要时间窗口提示。
* 用户自定义提醒。
* 提醒状态与确认记录。
* 官方公告变化提示。
* 设备通知能力检测。
* 通知权限和失败状态说明。

浏览器通知、后台运行和公告监测均存在平台及部署条件限制。只有在对应功能已实际实现并经过验证后，才能将其标记为可用。

五、跨设备体验

项目以响应式 Web 设计为目标，重点考虑：

* iPhone 与 iOS Safari。
* Android 与 Chrome。
* Windows 与 Chrome、Edge。
* macOS 与 Safari、Chrome。
* 不同屏幕尺寸。
* 触控与鼠标操作。
* 软键盘弹出时的布局变化。
* 深色和浅色显示模式。
* 系统减少动态效果设置。

跨平台兼容性应通过实际测试验证，不能仅根据 CSS 适配规则宣称所有设备均已通过测试。

大学风险核验原则

学校风险核验应基于明确证据，而不是简单的黑名单匹配。

核验维度

1. 学校名称是否能与适用的官方记录匹配。
2. 学校办学性质及学校类别是否明确。
3. 学校官方网站是否能够与该机构可靠关联。
4. 招生宣传主体是否与官方信息一致。
5. 招生电话、邮箱及相关联系方式是否来自可靠来源。
6. 是否存在主管部门发布的相关风险提示。
7. 当前数据是否过期，是否存在名称变更或信息歧义。

结果展示

查询结果可以采用以下状态：

* 已核验： 在指定范围内找到相匹配的权威记录。
* 待核验： 现有信息不足以得出可靠结论。
* 需要关注： 存在可说明、可追溯的异常。
* 高风险警示： 有权威公告或其他充分证据支持具体风险判断。

这些状态不是对学校所有行为的绝对保证。核验结论必须附带证据、时间和适用范围。

特别说明：未在某份名单中找到学校，并不必然证明该机构违法或虚假；域名后缀也不能单独用来判断学校资质。

隐私与数据安全

考生报名资料可能涉及高度敏感的个人信息，因此项目必须将数据保护视为基础要求，而不是附加功能。

数据最小化

* 只处理完成具体功能所必需的数据。
* 不因提供大学查询功能而要求用户填写个人资料。
* 不在无必要的情况下收集身份证号、家庭住址、联系方式或证件照片。
* 不将敏感数据用于广告或无关分析。

本地存储

如果某项功能声明资料仅保存在本机，则必须通过代码和实际运行验证：

* 数据是否写入浏览器存储。
* 是否存在额外的网络传输。
* 不同浏览器和设备之间是否会自动同步。
* 清除网站数据后哪些内容会丢失。
* 备份文件是否包含明文敏感信息。
* 用户能否查看、导出和删除自己的资料。

浏览器本地存储不天然等同于安全加密存储。涉及敏感数据时，应明确说明实际保护机制及其限制。

加密与访问控制

如果项目使用 PIN、密码或加密存储功能，应明确：

* 哪些数据实际受到加密保护。
* 加密和解密流程。
* 密钥如何生成、派生和保存。
* 锁定、解锁和错误尝试处理方式。
* 忘记密码后的恢复限制。
* 备份、恢复和删除流程。

不得将仅隐藏界面、简单编码或普通本地存储描述为可靠加密。

网络与第三方服务

* 不在公开前端代码中暴露秘密密钥。
* 不将敏感报名资料发送给无关第三方服务。
* 对外部数据源进行来源与可靠性检查。
* 避免在日志中记录不必要的个人信息。
* 对外部链接和数据内容进行安全处理。
* 对需要后端处理的功能说明数据流向、用途和保留期限。

技术与架构原则

项目具体使用的技术栈，应以仓库中的实际配置文件和源代码为准。

在项目文档中，不应凭空填写框架版本、数据库类型、部署架构或测试覆盖率。

建议围绕以下层次组织系统：

用户界面层

负责搜索、资料准备、提醒设置、查询结果、错误状态和响应式布局。

业务逻辑层

负责输入验证、报名阶段计算、风险规则、状态管理和操作流程。

数据层

负责官方名单、学校别名、联系方式来源、公告记录和数据版本管理。

外部信息层

负责访问经过确认的官方页面、公开数据或合法授权的数据服务。

安全边界

负责敏感数据保护、访问控制、输入校验、请求限制和错误处理。

并非所有层次都需要单独部署为服务。应优先采用与实际项目规模匹配、易于维护的架构。

开发与质量要求

项目开发应遵循可验证、可回归和可维护的原则。

建议覆盖：

* 输入校验测试。
* 报名时间边界测试。
* 高校名称匹配测试。
* 风险规则测试。
* 外部数据源异常测试。
* 敏感数据存储与删除测试。
* 搜索和详情交互测试。
* 键盘与弹层布局测试。
* 跨浏览器测试。
* 无障碍和减少动态效果测试。
* 构建、静态检查和自动化测试。

测试报告应记录实际执行的命令、结果、失败项及尚未覆盖的范围。

没有真实执行的测试，不得标记为通过。

开源与协作

本项目希望通过清晰的文档、可复现的开发步骤和明确的安全边界，降低参与门槛。

欢迎围绕以下方向开展贡献：

* 官方数据来源整理。
* 信息核验规则改进。
* 界面与交互体验优化。
* 响应式布局和无障碍改进。
* 隐私与安全审计。
* 测试用例完善。
* 文档纠错和使用体验反馈。

提交贡献时，应尽可能说明修改原因、影响范围、验证方法和已知限制。

涉及安全问题时，应优先采用负责任的报告方式，避免公开披露真实用户的敏感数据。

项目状态

项目当前状态、已完成能力和后续计划应根据仓库实际情况持续更新。

建议将功能状态划分为：

* 已实现并经过验证。
* 已实现但尚未完成充分验证。
* 正在开发。
* 计划开发。
* 受外部平台或数据源限制。

不要使用虚构的版本号、下载量、用户数量、测试覆盖率或性能指标来包装项目。

免责声明

山东高考报名助手是独立的辅助工具，不是政府部门或考试机构的官方产品。

本项目不保证所有第三方信息始终完整、实时或准确。用户应在重要操作前核对相关主管部门和官方报名系统发布的最新信息。

本项目不能替代正式报名流程，也不能保证用户具备报名资格、一定能够完成报名或获得录取。

涉及个人资料、报名提交、费用支付和其他具有实际后果的操作时，请用户本人仔细核对并通过官方渠道完成。

结语

高考报名涉及重要的个人信息和时间节点。我们希望通过更清晰的信息组织、更可靠的来源核验、更克制的交互设计和更严格的隐私保护，让考生能够更从容地完成准备工作。

项目的价值不在于展示多少功能，而在于每一个功能是否真实可用、每一条信息是否有据可查，以及每一次操作是否尊重用户的选择与隐私。

信息有来源，结论有依据，操作有边界，隐私有保障。
